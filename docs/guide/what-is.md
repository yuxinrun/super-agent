# 一句话讲透 Super-agent

Super-agent 是 DeepSeek Harness 团队在 **2026 年 10 月 31 日**公开的一套 **Agent 底层架构**（配套一个 MIT 许可的研究原型 `deepseek-ai/dsh-superagent-prototype`）。它想做的东西可以一句话说完：

> **把 Agent 从「你打开的一次对话」变成「一个一直在岗的同事」。**

注意这句话里没有一个字在讲模型参数。它讲的是**组织方式**——就像公司换的是排班表和流程，不是把员工换成更聪明的人。

## 它长什么样

<FourTraits />

四个特征不是四句口号，每一个都对应一个具体的工程模块。缺了模块，特征就只是形容词。

| 特征 | 通俗说法 | 靠哪个模块 | 没有它会怎样 |
| --- | --- | --- | --- |
| 连续性 | 不用重新解释背景 | 存算分离 | 关窗口即失忆，每次从头交代 |
| 高效性 | 几件事同时推进 | 双层架构 + 批处理 | 慢的任务把快的堵在门口 |
| 主动性 | 自己找活干 | 事件驱动 | 它只在你敲字时才存在 |
| 持久性 | 挂了能自己爬起来 | 外部 Watchdog | 进程一崩，任务原地蒸发 |

## 通俗版定义，和它的严格版

**通俗版**：一个一直在线、能同时干多件事、会主动找活干、出问题能自己恢复的 Agent。

**严格版**：一个由**系统层**接管会话管理与上下文同步的 Agent 系统。模型的注意力用来干活，调度、同步、恢复这些杂务下沉到基础设施。

两个版本的区别只在主语。通俗版说「Agent 很能干」，严格版说「**系统**替 Agent 把杂务干了」。这套架构的全部价值都在这个主语变化上：能力不是从模型里挤出来的，是从工程结构里省出来的。

## 它明确不是的东西

- **不是一个新大模型。** 不训练、不刷榜、不换推理能力。
- **不是一个可以下载安装开箱即用的产品。** 官方定位是**研究原型**，而且开源代码与跑出数据的内部版本**不完全一致**。
- **不是一个「一次任务里编排多个角色」的 Multi-Agent 框架。** 那条路 LangGraph、CrewAI 已经走在前面，两者解决的问题不在同一层（见 [它和 Multi-Agent 框架有何不同](./vs-others.md)）。
- **不是你在搜索引擎里撞到的那个 `superagent`。** npm 上有个 JavaScript 请求库、市面有几个同名销售产品，都跟这里无关（见 [这个词已经很挤了](../limits/name-collision.md)）。

从左到右：事件从真实工作现场涌进来；Router 先用便宜的规则过滤，只在真需要判断时才叫模型思考；Worker 各拿一个会话并行干活；记忆和看门狗都在模型外面。

::: tip 为什么这张图值得你花十分钟
如果你只打算记住一件事，请记住：**会话（session）不该由聊天窗口来管理。** 这个词在过去两年里默认等于「一次对话」，而 Super-agent 把它改成了「一个可恢复、可寻址、可以跨周存在的执行单元」。改动听起来很小，但它决定了一个 Agent 能不能被称为「同事」。
:::

## 想快速判断这套设计靠不靠谱

看三处细节，比看结论有用：

1. **它承认成本。** Router 的设计核心不是「更聪明」，而是「少想几次」——批处理把单次决定的推理时间从 6.4 秒压到 1.6 秒，这是账算得很细的做法。
2. **它做了消融。** 把「订阅直通」拆掉，Router 判断次数约涨 30%、读缓存 token 从 2323 万涨到 3177 万。愿意公布拆掉零件后的数据，说明这套模块不是画出来的。
3. **它留了问题。** 架构扩展性、跨实例通信（A2A）、安全与隐私都被明确列为未解。一份把困难写在里面的文章，比一份「全面落地」的 announcement 可信得多。
