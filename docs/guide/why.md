# 为什么 AI 越多你越累

先说结论：**当模型能独立干完一件活之后，节省下来的时间会被「管理模型」重新吃掉。** 这不是段子，这是过去两年几乎所有认真用 Agent 的人都撞上的墙。

DeepSeek Harness 团队把这面墙称作**注意力瓶颈**——模型执行单任务时的人工干预越来越少，于是瓶颈从「AI 会不会做」迁移到「人忙得过来吗」。

## 你现在大概在干第四种工作，而你以为自己在干第一种

<LayerArch />

一个真实的下午通常是这样过的：

1. 开一个窗口让它复现 bug，开第二个窗口让它写周报初稿。
2. 第三个窗口问你「要不要继续」，你切过去点确认——因为你不在，它就真的不动。
3. 第一个窗口查到关键线索，你把它复制下来，粘贴给第二个窗口当背景。
4. 你突然意识到自己已经不在写代码，你在**做调度**：分配任务、同步上下文、核对进度、重复自我介绍。

::: warning 这堵墙的隐蔽之处
它不会让任何一次任务失败。每一个窗口都干得挺好，代码能跑，答案也对。它消耗的是你的**切换次数**和**记忆带宽**——这两样东西没有日志，也没有 dashboard，所以你很难证明自己在做额外工作，直到某天发现一天开了 20 个会话。
:::

## 三种现存形态，各自的失效点

| 形态 | 它解决了什么 | 它在哪儿崩 | 崩的原因 |
| --- | --- | --- | --- |
| 单窗口 chat | 一次问答、一次小任务 | 任务一长就要你陪着 | 会话有始有终，没人值班 |
| 多窗口并行 | 同时推进几件事 | 上下文同步全靠人肉复制 | 窗口之间没有共享状态 |
| 单 Session + Subagent 工具 | 让模型自己派子任务 | 主会话的上下文越滚越大，你依然是唯一的总线 | 调度器是模型，不是系统 |

第三行是最多人现在用的方案，也是最容易高估的方案。它看起来已经是「AI 指挥 AI」了，但请注意：所有子任务的返回结果仍然要汇回**同一个上下文窗口**，会话本身仍然**有始有终**，仍然需要有人（你）在窗口外维持意图。它把执行并行化了，却没有把**记忆**和**调度**从模型里搬出来。

## Super-agent 换了哪个零件

它没有加能力，它做的是**把三件事从模型手里拿走**：

<div class="mp-steps">
  <div class="mp-step"><b>1</b><div><strong>会话管理，交给系统</strong><p>会话不再是聊天窗口的一种属性，而是一个可以被创建、恢复、寻址的执行单元。</p></div></div>
  <div class="mp-step"><b>2</b><div><strong>上下文同步，交给外部状态</strong><p>Worker 之间要共享的东西存在模型外面，不必由你复制粘贴，也不必全部塞回同一个窗口。</p></div></div>
  <div class="mp-step"><b>3</b><div><strong>存活判断，交给看门狗</strong><p>模型不负责确认自己还活着。外部进程盯心跳，卡死就重启。</p></div></div>
</div>

拿走的这三件事，恰好就是让你变成人肉调度器的那三件事。

## 一个不算准确的比喻，但它很好用

::: tip 把它想成公司，而不是想成大脑
你以前雇了一个很能干的临时工：每次来都要重新交代一遍项目背景，下班就忘光，你不在他就闲着。Super-agent 想做的不是找一个更聪明的临时工，而是**给你搭一个部门**——有个主管（Router）负责接电话和派活，有几个专员（Worker）各管一摊，有个档案室（外部状态）存所有背景，还有个保安（Watchdog）在下班后巡视谁还在工位上。

你从「工位的邻居」升成了「部门负责人」。你的新工作是提要求和签字。

这个比喻的失真之处也要说清楚：部门里的人有判断力、会推卸责任、会理解你的言外之意；Router 不会，它只会按你写的规则和大模型的推理办事。**别把组织比喻读成能力比喻。**
:::

## 为什么这件事值得写成一份手册

热度来得很快，误读来得更快。最常见的一句话是「DeepSeek 又发新模型了」——这句话里，**「模型」两个字恰好是这次发布里最不存在的东西**。真正值得读的是工程部分：一个 Agent 系统怎么处理常驻、并发、上下文和崩溃恢复。

这四个问题在任何一家做 Agent 应用的团队里都还在用人肉解决。它们不是 DeepSeek 的问题，是这个阶段的共性问题。只是这次有人把答案摊开写成了九章，还附了一个能翻的仓库。

<div class="mp-quote">判断一项 Agent 技术是不是真的进步，有个很朴素的标准：它有没有让你少开几个窗口。减少你手工动作的，是进步；只增加你能配置的东西的，是框架更新日志。</div>
