# 外部 Watchdog：给 Agent 配一个会思考的保安

一个常驻的 Agent 系统有一个新问题，是「用完即走」的 Agent 从来不需要的：**没人知道它现在是不是还活着。**

进程还在，但卡住了；模型还在返回，但一直在原地打转；任务还在跑，但方向早就偏了。这三种情况在监控指标上都长得一模一样——都是「还在运行」。

## 它是什么

Super-agent 在主架构之外设了一个**独立的 Watchdog Session**：

- 它**不在主循环里**，是体系外的一个独立会话；
- 它由**定时消息驱动**，自己构成一条外部控制回路；
- 它做两类事：处理接口报错这类**基础设施故障**，以及**用模型判断各 Worker 是否取得实质进展、方向是否偏离目标**；
- 发现异常时**介入修复**。

<LayerArch />

## 为什么必须由外部来做

因为「自己监督自己」在逻辑上就不成立。

::: tip 一个卡死的进程不会报告自己卡死了
这是运维领域最古老的常识，也是看门狗存在的全部理由。传统硬件看门狗的工作方式粗暴到不讲道理：主循环按时来喂狗，**没来就重启**，不问原因。它不需要理解程序在干什么，它只需要一个心跳。

Super-agent 保留了这层粗暴——接口报错、进程失联，这类判断不需要智能。**它多做了一步**：在心跳之外，用模型去判断语义层面的进展。也就是说，这个保安不光看你有没有回工位，还会看一眼你的屏幕，问你「这个问题你已经转了四十分钟，是不是该换个思路」。
:::

## 心跳 + 语义，两层判断

| 判断类型 | 问的问题 | 需要智能吗 | 动作 |
| --- | --- | --- | --- |
| 基础设施 | 它还喘气吗？接口报错了吗？ | 不需要 | 重启、重试、换实例 |
| 进展语义 | 它这一小时有没有实质推进？ | **需要** | 介入修复、纠偏 |
| 目标语义 | 它做的这件事还是你要的那件吗？ | **需要** | 介入，交回给人 |

第三行是最有价值也最危险的一行。前两个是可用性工程，第三个已经是**对齐工程**：一个被授权判断「方向对不对」的进程，本身就是一个需要被约束的 Agent。

## 「持久」这个特征在这里闭环

回到最初那四个特征——**持久 = 始终在线、异常自动恢复**。它完全依赖这一章：

<div class="mp-steps">
  <div class="mp-step"><b>1</b><div><strong>状态在模型外面</strong><p>见[存算分离](./storage-compute.md)。进程可抛弃，记忆不可抛弃。</p></div></div>
  <div class="mp-step"><b>2</b><div><strong>有人发现它停了</strong><p>独立 Session + 定时消息，不依赖主循环自证健康。</p></div></div>
  <div class="mp-step"><b>3</b><div><strong>有人决定怎么救</strong><p>基础设施问题直接重启；语义问题用模型判断是否纠偏。</p></div></div>
  <div class="mp-step"><b>4</b><div><strong>从断点继续</strong><p>因为状态在库里，重启之后不用从头交代。</p></div></div>
</div>

少了第 2 步，第 1 步毫无意义——状态存在数据库里，但没人去把它捞出来重新跑，那就只是一个更可靠的失败记录而已。

<div class="mp-quote">「自愈」不是一个动作，是一条回路：发现异常 → 判定性质 → 选择动作 → 恢复执行。四步里少任何一步，你就只是把崩溃日志写得更漂亮了。</div>

## 三个你必须自己回答的问题

本站的推演，不是原文内容，但只要你真去搭就会撞上：

1. **谁看着看门狗？** Watchdog 自己也是一个会话，也会卡。它需要一个外部心跳源——最终这条链子必须落到某个不由 Agent 自己控制的地方（进程管理器、cron、平台）。
2. **纠偏的权限边界在哪？** 「发现方向偏离就介入」意味着它有权改变正在运行的任务。这个权力给小了没用，给大了会出现一个自作聪明的保安把活干歪。
3. **谁审计它？** 一个能读写 Worker 状态、能重启任务的进程，必须留下完整的介入记录。否则故障归因会变成一个哲学问题：到底是谁搞坏的。

::: warning 这是这类架构共同的软肋
自主性越高，你就越需要一个能回答「刚才发生了什么、谁决定的」的系统。看门狗是这套架构里第一个**必须被严格审计**的角色，而原型阶段一般恰好没有把它做完。这也是官方把安全与隐私列为开放问题的原因之一（见[还没解决的问题](../limits/open-problems.md)）。
:::
