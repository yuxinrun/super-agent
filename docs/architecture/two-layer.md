# 双层架构：Router 只管事，Worker 只管活

如果整套 Super-agent 只能记住一个设计，记这个：**把一个 Agent 拆成两层——一个常驻的主管，和一群短命的执行者。**

## 两层的准确分工

| 维度 | Router 层 | Worker 层 |
| --- | --- | --- |
| 生命周期 | **常驻**，一直在跑 | 任务级，用完可以结束 |
| 面向谁 | 面向人，所有信道进来的交互都由它接 | 面向 Router，不直接对用户说话 |
| 管什么 | 全局协调、全局记忆、任务分派、结果汇总 | 一件具体工作：读资料、调工具、产出结果 |
| 手上有什么 | **没有工具** | 有工具，还能再派 Subagent 拆细活 |
| 上下文 | 维护全局的「谁在干什么、和谁有关」 | 各拿一份隔离的会话上下文 |
| 思考频率 | 越省越好（批处理 + 直通分流） | 越专注越好（只面对一个任务） |

一句话：**Router 决定「做什么、谁去做、结果给谁」；Worker 决定「怎么做」。**

## 为什么 Router 手上一个工具都不给

这是整个设计里最反直觉、也最聪明的一刀。

正常做法是给主管配上所有工具，让它「必要时自己动手」。Super-agent 不给。**没有工具，它就物理上无法亲自下场干活**——它想替你跑那个测试也跑不了，只能把活派出去。

::: tip 这条约束是从实验里长出来的
在团队的对照实验里，中性提示下的单 Session 方案，即使配备了 Subagent 工具，**五次运行一次都没有委派**——模型全自己闷头干了。换上「优先委派」的提示词，五次里四次委派了，但完成时间仍然慢于 Super-agent；而且仍然出现过「任务太小我自己来」的情况。

这说明一件事：**用提示词请求模型自律，是个不可靠的工程前提。** 你要求它别插手，它就会插手。与其写三段话恳求，不如把它的手拿走。架构约束比行为约束便宜，也比它可靠。
:::

这跟操作系统里的权限分级是一个道理：内核态负责调度，用户态负责计算。你不希望调度器自己跑去算浮点。

## Worker 为什么不直接回你消息

因为**你需要一个单一的对话对象**。

如果每个 Worker 都能给你发私信，你会在五个渠道里收到五条「这个做完了」「那个要确认」「第三个失败了」，然后你又要开始人肉汇总——那就是这套架构想消灭的东西。

所以 Worker 把状态和结果汇报给 Router，由 Router 统一对外沟通。你在群里 @ 的那个 AI，永远只有这一个。

<div class="mp-quote">这就是「连续」这个特征的真正含义：不是它记性好，是你不需要记它的组织架构。你只认识一个同事，背后有几个进程在干活，是它自己的事。</div>

## Worker 的两件关键能力

1. **订阅 Thread。** 拿到任务后，Worker 可以直接订阅与之相关的事件线。后续相关消息由程序**直接送到它手里，不必每次经过 Router**。消融实验量过这条捷径的分量：把它拆掉，Router 的判断次数会多出约 30%（见 [事件驱动](./event-driven.md)）。
2. **再派 Subagent。** 双层不等于「只有两层」。Worker 碰到细分工作时可以继续拆子任务。区别在于：这里的委派发生在**一个隔离会话内部**，而不是把所有细节汇回同一个上下文窗口。

## 上下文为什么会爆炸

这是双层架构在解决的那个原始问题。单 Session 方案里，随着并行任务增多，一个窗口要装下：

- 三个任务的原始指令与全部来回
- 每个任务查到的资料
- 每次失败的报错和重试过程
- 你自己的三次改口

结果是同一个窗口既要当**工作记忆**又要当**档案室**。模型看到的工具定义和历史记录越多，它判断「现在该做什么」就越贵也越容易错。双层的解法很工程：**主管只保留索引，细节留在各自 Worker 的会话里，需要时沿引用找回。**

| 方案 | 上下文里有什么 | 代价 |
| --- | --- | --- |
| 单窗口硬扛 | 所有任务的全部细节 | 窗口膨胀、成本上升、模型更容易忘记委派 |
| 单 Session + Subagent | 子任务结果仍汇回主窗口 | 主窗口依然是瓶颈，生命周期依然有始有终 |
| 双层 + 状态外置 | Router 拿全局索引，Worker 拿各自上下文 | 需要一套引用与找回机制（Inline / Spill / 链式召回） |

## 换成人的语言

<FourTraits />

::: warning 别把比喻读成承诺
「虚拟团队」这个说法很好懂，但它会带走一个重要信息：**Router 不是人**。它不会因为你没交代清楚就主动来问第二次（除非你让它这么设计），也不会在发现任务其实不该做时擅自停下。组织比喻用来降低理解成本，不用来替代能力评估。
:::

## 想自己搭一层的话，注意这三件事

1. **主管会变成单点。** 所有交互都过 Router，它挂了等于整个 Agent 挂了。这也是为什么需要外部 [Watchdog](./watchdog.md) 看着它。
2. **委派需要成本预算。** 无限制开 Worker 会让 token 与并发数失控——直通机制存在的理由之一就是这个。
3. **边界要写死，不要写成建议。** 「Router 不配工具」是一种实现选择，不是文档里的行为准则。如果你的框架只在提示里写「请不要自己执行」，你会得到那个五次都没委派的实验结果。

<div class="mp-quote">好的架构不做道德教育，它做物理隔离。</div>
